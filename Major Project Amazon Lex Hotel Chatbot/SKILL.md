# Skill: Create-SKILL (agent-customization) — Cloud Project Variant

## Purpose
Provide a reusable, workspace-scoped procedure for extracting a multi-step cloud-computing workflow from a conversation and encoding it as `SKILL.md` to guide agents working on cloud projects. Focus areas: cloud provider selection, infrastructure-as-code (IaC), CI/CD, security, monitoring, cost controls, and deployment verification.

## Scope
- Default: workspace-scoped (saved at repository root) and tailored for cloud-native projects.
- Can be adapted for personal/global use; confirm if the user prefers team vs personal scope.

## Inputs
- Conversation transcript or relevant message history describing the workflow.
- Workspace files: code, IaC templates (Terraform/ARM/CloudFormation), CI configs, README, and deployment scripts.
- Constraints: target cloud provider(s), compliance requirements, budget/cost limits, and environment topology (dev/staging/prod).

## Outputs
- A `SKILL.md` file saved in the workspace (root by default).
- A short summary listing ambiguous items and targeted clarifying questions.
- Example prompts and a sample checklist for running the workflow against a chosen cloud provider.

## When to Use
- Formalize cloud deployment, testing, or operational workflows discussed in conversation.
- Convert ad-hoc cloud operations into reproducible, automatable instructions for agents.

## Step-by-step Procedure
1. Review conversation context and any referenced workspace files, especially IaC and CI configs.
2. Map the high-level workflow: build → test → package → deploy → verify → monitor.
3. Extract decisions and branches: cloud provider choice, region, instance sizing/scaling, blue/green vs canary, rollback criteria.
4. Capture security and compliance checks: secrets management, IAM roles, network segmentation, vulnerability scans.
5. Define measurable completion checks: successful CI run, smoke tests passing, endpoint health checks, monitoring alerts suppressed, cost within budget.
6. Draft skill content: name, purpose, inputs, outputs, explicit steps, decision points, checks, provider-specific notes, and example prompts.
7. Save as `SKILL.md` at the chosen location and present ambiguous items for clarification.
8. Iterate with the user; after acceptance, optionally add provider-specific subfiles (e.g., `SKILL.aws.md`) or register examples in `prompts/`.

## Cloud-Specific Decision Points
- Provider selection: AWS/GCP/Azure/Other — impacts IaC templates and CLI tools used.
- Deployment model: serverless, containerized (ECS/EKS/GKE/AKS), VM-based, or PaaS.
- State management: remote backend for IaC (S3/GCS/Azure Blob + locking) vs local.
- Secrets/storage: use managed secrets (Secrets Manager/Parameter Store/Key Vault) vs environment variables.
- CI/CD: GitHub Actions, GitLab CI, Azure Pipelines, or Jenkins — choose preflight checks and promotion gates.

## Quality Criteria / Completion Checks
- Each step is actionable, with the exact command or IaC file referenced.
- Decision points include consequences and recommended defaults.
- Completion checks are measurable: CI status, integration test results, endpoint health, logs/metrics baseline, and cost projection check.
- Security gates exist: vulnerability scan results, IAM least-privilege review, and secret rotation checks.

## Example Prompts (cloud-focused)
- "Create a SKILL.md that formalizes our AWS Terraform deploy workflow with CI/CD and rollback criteria."
- "Draft a SKILL.md for GCP serverless deployment including cost checks and monitoring setup."
- "Turn our staging→prod promotion steps into a SKILL.md with measurable completion checks and IAM review."

## Ambiguities to Confirm
- Preferred cloud provider(s) and any provider-specific constraints.
- Desired level of provider detail (generic vs provider-specific step templates).
- Target locations for skill/examples (repo root vs `prompts/` or `docs/`).

## Suggested Next Steps After Drafting
1. Confirm cloud provider and preferred IaC/CI tools.
2. If provider-specific, generate subfiles (e.g., `SKILL.aws.md`) with concrete commands and sample IaC snippets.
3. Add example runs and a minimal `README.md` snippet explaining how to invoke the skill.
4. Optionally register the skill in a `prompts/` folder for discoverability.
